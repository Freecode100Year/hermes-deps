怎么用

先预检，再安装

官方安装器的每项依赖都是「先探测、存在就跳过」，并且自带 --ensure 这个只装依赖不装本体的入口。所以预装不是绕过它，而是它本来就支持的路径。 

# 1 · 体检：只检测，不改动系统
$ bash hermes-preflight.sh --check

# 2 · 装齐依赖（需要 root）
$ sudo bash hermes-preflight.sh --yes

# 3 · 依赖就绪后，正式安装 Hermes
$ curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
$ source ~/.bashrc && hermes doctor

只想用官方通道、不用脚本，最小可行的一条是 curl -fsSL <install.sh> | bash -s -- --ensure node,browser,ripgrep,ffmpeg —— 它只装依赖，不 clone 仓库、不建 venv。

Debian 13 与 Ubuntu 24.04+ 做过 time_t 转换，libasound2 之类改名成了 libasound2t64（libatk1.0-0、libcups2、 libatspi2.0-0、libglib2.0-0 同理）。别硬编码映射表 —— 对每个候选名用 apt-get install -s 模拟安装探测，t64 变体优先 —— 不能用 apt-cache show，它对 libasound2 这种被 Provides 的虚包会返回成功，但实际装不上。

install.sh 的 node_satisfies_build() 已从单一下限变成三段式 22.22+ / 24.11+ / 26+ （nanoid 6 排斥 23、25；@babel/* 8.x 要求 ^22.18.0 || >=24.11.0）。预检脚本只装 22.x / 24.x / 26.x 各自最新版，落点都在这些区间内，不受影响；但机器上已有的系统 Node 若恰好卡在空档 （23.x、25.x 或 24.0–24.10），预检原先的『已存在，跳过』判断会比官方安装器宽松 —— 已改成按同样的三段式校验。

install.sh 从 v26.7.0 起额外在 Debian/Ubuntu 上装 libatomic1 —— Node 官方 linux-x64 二进制链接了 libatomic.so.1，精简镜像不带，缺失时下载下来的 Node 直接无法启动（上游 issue #87460）。预检脚本的 Stage 2 基础包已跟进加入。

已知坑

照着官方文档做也会炸的四个地方

撤源

Debian 11 的 apt 源即将消失

bullseye 的 LTS 在 2026-08-31 到期，之后官方源撤到 archive.debian.org，apt-get update 直接失败， 后面所有包安装全部连带失败。

处理：改写 sources.list 指向 archive， 并关掉 Check-Valid-Until；原文件带时间戳备份， sources.list.d 里的失效条目一并注释。

已澄清

Node 二进制的 libc 门槛

Node 官方 Linux x64/arm64 二进制的 tier-1 下限是 glibc ≥ 2.28、 libstdc++ ≥ 6.0.25（GLIBCXX_3.4.25）。bullseye 是 glibc 2.31 + GLIBCXX_3.4.28 —— 满足要求，Node 26 本身跑得起来。

处理：仍然下载解包后先跑一次 node -v 再决定装不装， 跑不起来自动降大版本。零成本的保险，也覆盖更老的衍生发行版。

不兼容

Playwright 不再支持 bullseye

playwright install --with-deps 在 bullseye 上会报 “only Ubuntu is supported”，或者装完仍漏库，浏览器起不来。

处理：自己按包名装齐运行库，只跑不带 --with-deps 的 npx playwright install chromium， 最后用 ldd chrome | grep "not found" 实测校验。

版本黑名单

npm 11.10 – 11.16 会被安装器拒绝

这几个版本因 .npmrc 兼容问题被官方安装器明确拒绝， 撞上了会在依赖安装阶段直接停下。

处理：预检时比对区间，落在里面就 npm i -g npm@11.9.2 换出来。Node 22 自带的 npm 10.x 不受影响。

六个阶段，每个都可重入

失败即停并打印原因；重复执行时已完成的阶段会直接跳过。

  1. 00环境判定 读 /etc/os-release 确认 apt 系；记录架构、glibc、libstdc++ 最高 GLIBCXX
  2. 01apt 源可用性 试跑 apt-get update；Debian 11 撤源场景下经授权改写到 archive，原文件备份
  3. 02基础系统包 ca-certificates、curl、git、xz-utils、build-essential、python3-dev、libffi-dev、ripgrep、ffmpeg
  4. 03Node.js 下载后实际执行 node -v 验证，24 → 22 降级；npm 撞黑名单则换 11.9.2
  5. 04uv + Python 3.11 uv 装到 /usr/local/bin，Python 预置到与安装器一致的目录，sudo 场景下顺带给原用户也备一份
  6. 05Chromium 运行库按 t64 择一安装，浏览器不带 --with-deps，最后 ldd 实测缺库
  7. 06官方 --ensure 兜底 跑一次官方依赖通道查漏，然后打印就绪报告
